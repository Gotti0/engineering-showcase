## 배경

채용용 GitHub Pages는 사례·근거·GitHub로 이어지는 하이퍼링크 중심이었고, 직전 계약 민감도 점검에서 private 런타임·알파 경로로의 딥링크 리스크가 드러났다. 기존 포트폴리오 HTML은 이미 슬라이드 형식이었다.

## 문제

페이지 간 `<a href>`와 마크다운 GitHub 링크가 있으면 (1) 슬라이드 발표 흐름이 깨지고 (2) private 레포·알파 관련 URL이 공개면에 섞일 여지가 있다. 내비·푸터·사례 목록의 링크를 유지한 채 문구만 바꾸는 방식은 부족하다.

## 결정과 근거

공개면을 세로 슬라이드 덱(커버→프로필→배경→스택→프로젝트→사례 2→근거→클로징)으로 재구성하고, 브랜드·내비·푸터·연락처에서 앵커를 제거했다. `stripMarkdownLinks`/`stripHtmlAnchors`로 md 렌더 결과의 링크를 라벨만 남긴다. 프로젝트 표기는 `Private live runtime` 등 평문으로 두고 레포 URL을 넣지 않는다. 멀티페이지 딥링크 UX는 버리고, `/p/<token>`·cases·evidence도 동일하게 링크 없는 슬라이드 셸을 쓴다. 인쇄용 16:9 페이지 브레이크 CSS는 유지한다.

## 검증

2026-11-10 `npm run build`로 정적 페이지 13개 생성. `dist/index.html`·evidence·persona에서 `<a` 앵커 0건. `features_backtester` URL·스토캐 파라미터 문자열 미포함. stylesheet용 `link href`(폰트)만 존재.

## 미해결

배포 후 라이브 Pages 재확인 필요. `/cases/` 등 구 URL은 빌드에 남지만 랜딩에서 안내하지 않음. audience md 원본의 마크다운 링크 문법은 렌더 시 제거되나 소스 파일에는 남아 있음.
