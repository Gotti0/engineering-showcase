## 배경

채용 담당자가 다른 회사용 맞춤 경로를 같은 사이트 UI에서 보면 안 된다는 요구가 있었다.

## 문제

퍼블릭 GitHub Pages에서는 URL·소스 접근을 막지 못한다. 랜딩에 회사 목록과 `/for/<회사슬러그>`가 있으면 UX상 격리가 성립하지 않는다. 인증형 격리는 Pages 범위를 벗어난다.

## 결정과 근거

UX 격리를 선택했다. 랜딩·내비에서 회사·직무 목록을 제거하고, 추정 어려운 `/p/<token>/`만 공유한다. 페르소나 페이지에 noindex를 넣고 교차 링크를 없앴다. Cloudflare Access 등 실질 격리는 하지 않았다. 토큰은 퍼블릭 소스에 있으므로 레포 열람까지는 막지 않는다.

## 검증

2026-11-10 `npm run build`에서 `/for` 없음·랜딩에 회사명 미포함·`/p/<token>/` 5개·페르소나 noindex를 확인했다. `npm run share-urls`로 공유 URL을 출력했다. Pages 배포 후 라이브 확인은 배포 단계에서 한다.

## 미해결

퍼블릭 `audiences/*.md`와 소스의 토큰 매핑은 레포를 열면 보인다. 실질 격리가 필요하면 private 배포로 옮겨야 한다.
