# 주문·운영 안전성

## 문제와 역할

비동기 작업에서 주문 상태가 겹치는 문제, 증권사 API와 분석 환경의 제약, 실패가 운영자에게 드러나지 않는 문제를 다뤘습니다. 개인 개발 시스템에서 AI 코딩 에이전트와 함께 구현·수정했습니다.

## 구현 구조

유한 상태 머신과 asyncio.Lock으로 주문 상태 전이를 검사했습니다. 32비트 증권사 API와 64비트 분석 환경은 WebSocket 브릿지로 분리했습니다. 다른 시스템에서는 추천 경로의 조용한 실패를 경고 이벤트와 주문 한도로 드러냈습니다. FastAPI 제어 API와 Docker·docker-compose 배포도 다뤘습니다.
구조도·개념 ERD(assets/diagrams/order-and-operation-safety.md)는 FSM·브릿지·주문 이벤트 논리 모델입니다.

## 근거와 한계

주력 근거는 비공개 런타임의 주문 FSM·브로커 실행·원장·제어 API입니다. 경로 목록은 근거 목록 PRIV-01~10을 따릅니다. 면접에서 스크린공유로 확인합니다.
공개 브릿지 프로젝트에서 환경 분리 구조의 공개 선조를 볼 수 있습니다. 실제 계좌·키·배포 시크릿은 포함하지 않습니다.
처리 지연 성과나 오류의 완전한 부재를 주장하지 않습니다. 운영 경험 설명은 현재 시스템 상태를 확인하는 자료가 아닙니다.
예제(examples/demo.py)는 메모리 내 상태 전이만 수행하며 주문 전송·네트워크 접근이 없습니다.
